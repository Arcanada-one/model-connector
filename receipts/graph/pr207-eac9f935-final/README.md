# PR207 exact-head parity evidence

The route-sweep candidate process was built from source commit `eac9f9354f742ea628a4378b725fd28e3c4b79f9` (tree `d51dbdc39c4ca4bed9be183764fd3b05f01d122f`). Its exact source-bound route sweep measured 66 verified responses and four 5xx responses; the process canary measured 13/13 code units. Raw plans, results and source pins are preserved here.

The four non-verified responses were repeated against the candidate and `origin/main` source commit `bb70aae82e78678dfb4e8f13621582ae6bd8cf74`, using one shared request plan and one probe program. The shared request plan digest is in `same-request-parity/result.json`; body bytes and the no-egress shim are identified by SHA-256. Both versions received the same three synthetic authentication headers and identical request bodies. For each request, candidate and main had the same status, response byte count and response SHA-256: the intent read and DeepSeek chat returned `503`, while the STT routes returned `500`. These are measured baseline outcomes, not passes. The admission input must retain tracked debt exemptions for strict-chat debt `709559c4-2ff7-4e2a-a69e-3b5de1dd2ce7` and STT debt `cb07a5b3`, with owner, expiry, plan digest and parity numbers in each reason.

The reviewed no-egress shim and same-request probe are stored as non-executable `.txt` evidence (`same-request-parity/noegress.cjs.txt` and `same-request-parity/probe.mjs.txt`); their exact content hashes are in the parity result. The no-egress shim blocks non-loopback `fetch`, `net.connect`, and `tls.connect` before a socket is opened. Host summaries are process-lifetime aggregates that include provider warm-up; their timestamp-free log format does not support per-request attribution. The harness does not prove absence of escaped descendants, and embedding/Ollama were not replaced by fakes. No live provider response was measured.

N1 is covered by the source change at `catalog-refresh.service.ts` and its exact-head regression test; the 13-probe process result includes that service's spec. Source review, admission, hosted CI, merge and deployment are separate checks and are not claimed by these canary files.
